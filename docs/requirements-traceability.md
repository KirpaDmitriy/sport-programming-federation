# Реестр требований «ФСП / Карьера»

Документ объединяет обновлённое ТЗ ФСП 2026, исходную постановку хакатона и
продуктовую идею автора. Обновлённое ТЗ имеет приоритет при конфликте. Статус
`готово` допустим только при наличии указанного проверяемого доказательства.

## Источники и приоритет

1. Обновлённое ТЗ: `ФСП спец. трек ТЗ.pdf`, 9 страниц, версия 2026.
2. Исходная постановка из первого запроса.
3. Авторская концепция графов компетенций и доказательств.

Единственное содержательное расхождение источников касается данных ФСП.
Исходная постановка обещала спецификацию API или мок-сервис, а обновлённое ТЗ
прямо говорит, что API, структура реестра и датасеты не предоставляются.
Следуем обновлённому ТЗ: используем маркированные синтетические данные и
собственный версионированный контракт. Наличие реальной истории ФСП не является
условием регистрации, пустая история обрабатывается штатно.

Авторская концепция не противоречит ТЗ. Граф навыков, граф требований,
достоверность, разность графов, выбор принимаемых соревнований и рекомендации
соревнований шире обязательного объёма, но напрямую усиливают объяснимость и
практическую ценность подбора — главный критерий с весом 35%.

## Критерии оценки и стратегия

| Вес | Критерий | Что должно быть видно жюри |
| ---: | --- | --- |
| 35% | Новая механика подбора | Работодатель получает объяснимый топ и сам инициирует контакт |
| 25% | Тестирование, валидация, категоризация | Вариативный сопоставимый тест и измеримые результаты устойчивости |
| 10% | Интерфейс | Два понятных сквозных пути без устных подсказок |
| 7% | Техническая проработка | Чистые слои, безопасность, скорость, интеграционные границы |
| 6% | Полнота и документация | Все обязательные этапы, включая кандидата без ФСП |
| 7% | Дополнительный функционал | Отклики, задачи, anti-fraud/ATS-концепция, адаптивность |
| 10% | Питч | Ясная презентация и демонстрация принятых решений |

## Принятые продуктовые решения

- Название продукта — **«ФСП / Карьера»** (прежнее рабочее название — «Выготский»).
- Публичная главная остаётся интерактивной демо-витриной. Боевой контур начинается
  с регистрации/входа и работает с данными текущего пользователя.
- Локальная email/password авторизация и серверные сессии обеспечивают рабочий
  MVP. Транспорт подтверждения email заменяемый: SMTP в эксплуатации и явный
  demo-outbox без притворства, что письмо реально отправлено.
- Будущий Keycloak подключается как OIDC-адаптер к той же внутренней записи
  пользователя; доменные ID не зависят от провайдера авторизации.
- Демонстрационные профили никогда не выдаются за реальные данные ФСП.
