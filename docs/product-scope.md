# Контракт MVP

Этот документ связывает постановку хакатона и продуктовую идею с проверяемыми
результатами. Пункт считается выполненным только при наличии указанного
доказательства.

## Сценарии

| Требование | Реализация MVP | Доказательство |
| --- | --- | --- |
| Отраслевая площадка для ИТ | Каталог ИТ-вакансий и профилей с ролями, грейдами, стеком и форматом работы | Экран каталога, `GET /api/v1/vacancies`, API-тест |
| Обратный подбор | Работодатель сначала выбирает вакансию и категорию, затем получает ранжированный список кандидатов | Экран работодателя, `GET /api/v1/vacancies/{id}/matches`, API-тест |
| Контакт с вакансией и зарплатой | Работодатель отправляет персональное предложение с зарплатной вилкой и сообщением | Форма предложения, `POST /api/v1/offers`, тест валидации зарплаты |
| Автоматическая категоризация | Категории и грейд рассчитываются из подтверждённых компетенций, а не вводятся кандидатом | Доменный сервис профилирования и параметризованный тест |
| Подтверждаемая квалификация | Каждая оценка компетенции содержит источник, результат, роль, разряд и уверенность | Карточка кандидата, `GET /api/v1/candidates/{id}`, доменный тест |
| Интеграция с ФСП | Адаптер принимает дисциплины, соревнования, результаты, роли и разряды по версионированному контракту | `POST /api/v1/integrations/fsp/sync`, мок-данные, контрактный тест |
| Агрегация разных источников | Доказательства имеют источник и внешний идентификатор; повторный импорт идемпотентен | Два источника в демо, тест повторной синхронизации |
| Граф компетенций | Навыки, зависимости и доказательства показаны как связный граф | Интерактивный граф на экране кандидата и JSON-представление в API |
| Достоверность компетенций | Уровень навыка отделён от уверенности; расчёт объясним до отдельного результата | Расшифровка оценки на экране, тест формулы |
| Граф требований вакансии | Работодатель задаёт требуемый уровень и критичность каждого навыка | Редактор вакансии, `POST /api/v1/vacancies`, тест валидации |
| Разность графов | Сервис показывает покрытие, дефицит уровня и неподтверждённые критичные навыки | Экран сравнения, endpoint матчей, доменный тест |
| Рекомендации соревнований | Для каждого пробела предлагаются релевантные предстоящие соревнования | Блок развития кандидата, тест ранжирования рекомендаций |
| Политика доказательств | Работодатель выбирает допустимые соревнования или доверяет рейтингу платформы | Настройка вакансии, тест обеих политик |
| Рейтинг соревнований | Учитываются массовость, сложность, официальность и тематическая релевантность | Объяснение оценки в API и тест граничных значений |
| Тематическая релевантность | В MVP используется воспроизводимое сопоставление тегов без внешней модели; интерфейс данных допускает позднюю офлайн-переоценку | ADR и тест сопоставления |
| Обратная связь кандидату | Кандидат видит предложения, причины совпадения, дефициты и следующий шаг | Экран кандидата и API-тест |
| Выразительный ИТ-дизайн | Адаптивный интерфейс использует яркие акценты, контрастные формы, ясную типографическую иерархию, живой граф и осмысленное движение | Визуальная проверка desktop/mobile, скриншоты и accessibility smoke test |
| Связь с хакатоном и ФСП | В интерфейсе явно указан источник спортивных данных; официальные знаки используются только при наличии пригодного исходника и права на применение | Экран «О данных», перечень источников и визуальная проверка |

## Поставка

| Результат | Доказательство |
| --- | --- |
| Работающий веб-сервис | Публичный URL и production smoke test |
| Исходный код в приватном репозитории | История гранулярных коммитов в `KirpaDmitriy/sport-programming-federation` |
| Документированное API | OpenAPI `/docs` и сохранённая схема `docs/openapi.json` |
| Инструкция по развёртыванию | `docs/deployment.md`, unit systemd и скрипт smoke test |
| Краткая техническая документация | `docs/architecture.md` и разделы README |
| Тесты функциональности | Доменный, контрактный и API-наборы; отчёт CI |
| Offline CPU path | Запуск и тесты не требуют GPU, внешней модели или сети |
| Проверенный интерфейс | Desktop/mobile render, отсутствие переполнений и доступные контрасты |

## Не входит в MVP

- промышленный OAuth и проверка личности;
- автоматический сбор данных без предоставленного API ФСП;
- обучение нейросетевой модели;
- платёжные функции и массовая рассылка.

Эти ограничения не подменяют заявленные сценарии: демонстрационные пользователи,
мок ФСП и детерминированная оценка должны проходить весь пользовательский путь.
